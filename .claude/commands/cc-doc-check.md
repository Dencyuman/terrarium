# /cc:doc-check - ドキュメント整合性チェック

## トリガー

- 実装変更後にドキュメントの更新漏れを確認したい
- コードコメントと実装の乖離を検出したい
- コンテキストエンジニアリングの品質を評価したい
- 古いTODO/FIXMEや不要なコメントアウトコードを発見したい

## 使用方法

```

/cc:doc-check [path]

```

引数:

- `path`: チェック対象のファイル/ディレクトリ（省略時はプロジェクト全体）

## 動作フロー

1. **発見**: Markdownファイルとソースコードファイルを収集
2. **分析**: ドキュメント記述と実装を照合
3. **検証**: コメント、構造、コマンド、パターンの整合性を確認
4. **評価**: コンテキストエンジニアリングの品質を評価
5. **レポート**: 重要度別に発見事項を報告

主要な動作:

- ドキュメントと実装の徹底的な照合
- コードコメントの品質と正確性の検証
- 未解決TODO/FIXMEの検出
- コメントアウトコードの発見
- AI向けドキュメントの質の評価
- 大量コンテキスト使用による深い調査

## ツール連携

- **Glob**: Markdownとソースコードファイルの発見
- **Grep**: パターン検索、TODO/FIXME検出、コメント抽出
- **Read**: ファイル内容の詳細読み込み
- **Bash**: コマンド実行可能性の検証

## 主要パターン

### ドキュメント vs 実装の整合性

- **[architecture.md](http://architecture.md)**: 記述されたディレクトリ構造 vs 実際の構造
- **[coding-standards.md](http://coding-standards.md)**: 規約 vs 実際のコード
- **[README.md](http://README.md)**: コマンド例 vs 実行可能性
- **[CLAUDE.md](http://CLAUDE.md)**: 説明・例 vs 実際の実装パターン

### コードコメントのチェック

- **Python**: docstring、# コメント
- **TypeScript/JavaScript**: JSDoc、//、/* */
- **Terraform**: # コメント

検証項目:

- コメントとコードの不一致（古い/間違った説明）
- 未解決マーカー（TODO/FIXME/HACK/XXX/NOTE）
- コメントアウトされたコード（削除候補）
- ドキュメントとコメントの説明の食い違い

### コンテキストエンジニアリング評価

- [README.md](http://README.md) の存在と品質
- [architecture.md](http://architecture.md) / [coding-standards.md](http://coding-standards.md) の存在
- AI可読性（構造化、テーブル、チェックリスト）
- 人間向け vs AI向けドキュメントの分離

## 例

### プロジェクト全体チェック

```

/cc:doc-check

# 全Markdownとソースコードを徹底調査

# ドキュメント-実装の乖離を検出

# 時間をかけて深く分析

```

### 特定ディレクトリのチェック

```

# Backendのドキュメントと実装を検証

```

```

/cc:doc-check management/docs/[architecture.md](http://architecture.md)

# 指定ドキュメントと関連実装を照合

# 記述内容の正確性を検証

```

## チェック項目詳細

### 1. ドキュメント-実装整合性

- ディレクトリ構造の一致
- ファイル命名規則の遵守
- コマンド/スクリプトの実行可能性
- コード例の正確性
- 依存関係の最新性
- 環境変数/設定の正確性

### 2. コメント品質

- docstring/JSDocの存在と正確性
- インラインコメントと実装の一致
- TODO/FIXME/HACK の未解決検出
- コメントアウトコード（削除候補）
- 古い・無効なコメントの検出

### 3. コンテキストエンジニアリング

- 必須ドキュメントの存在確認
- AI可読性の評価
- 構造化の程度（テーブル、リスト、チェックリスト）
- 重複・矛盾の検出

## 境界

**実施すること:**

- ドキュメントと実装の徹底的な整合性チェック
- コードコメントの品質と正確性の検証
- TODO/FIXME/コメントアウトコードの検出
- コンテキストエンジニアリングの質の評価
- 大量コンテキストを使用した深い調査

**実施しないこと:**

- ドキュメントやコードの自動修正（cc:doc-sync で実施）
- 外部リンクの有効性チェック（範囲外）
- コードの機能的な正確性テスト（cc:test で実施）
- リンク切れチェック（重要度低）
