# /cc:improve - コード改善

## トリガー

- コード品質向上とリファクタリングのリクエスト
- パフォーマンス最適化とボトルネック解決のニーズ
- 保守性改善と技術的負債の削減
- ベストプラクティス適用とコーディング規約の強制

## 使用方法

```

/cc:improve [対象] [--type quality|performance|maintainability|style] [--safe] [--interactive]

```

オプション:

- `--type`: 改善の種類（品質/パフォーマンス/保守性/スタイル）
- `--safe`: 安全なリファクタリングモード
- `--interactive`: 対話的モード

## 動作フロー

1. **分析**: 改善機会と品質問題のためにコードベースを調査
2. **計画**: 改善アプローチを選択し、専門知識のために関連ペルソナを起動
3. **実行**: ドメイン固有のベストプラクティスで体系的な改善を適用
4. **検証**: 改善が機能を保持し、品質基準を満たすことを確認
5. **文書化**: 改善サマリーと今後の作業への推奨事項を生成

主要な動作:

- 包括的な検証とロールバック機能による安全なリファクタリング

## ツール連携

- **Read/Grep/Glob**: コード分析と改善機会の特定
- **Edit**: 安全なコード変更と体系的なリファクタリング
- **Bash**: テスト実行と検証

## 主要パターン

- **品質改善**: コード分析 → 技術的負債の特定 → リファクタリング適用
- **パフォーマンス最適化**: プロファイリング分析 → ボトルネックの特定 → 最適化実装
- **保守性向上**: 構造分析 → 複雑度削減 → ドキュメント改善
- **セキュリティ強化**: 脆弱性分析 → セキュリティパターン適用 → 検証確認

## 例

### コード品質向上

```

/cc:improve src/ --type quality --safe

# 安全なリファクタリング適用による体系的な品質分析

# コード構造を改善、技術的負債を削減、可読性を向上

```

### パフォーマンス最適化

```

/cc:improve api-endpoints --type performance --interactive

# Performanceペルソナがボトルネックと最適化機会を分析

# 複雑なパフォーマンス改善決定のための対話的ガイダンス

```

### 保守性改善

```

/cc:improve legacy-modules --type maintainability --preview

# Architectペルソナが構造を分析し、保守性改善を提案

# プレビューモードでレビューのために適用前に変更を表示

```

### セキュリティ強化

```

/cc:improve auth-service --type security --validate

# Securityペルソナが脆弱性を特定し、セキュリティパターンを適用

# セキュリティ改善が効果的であることを包括的に検証

```

## 境界

**実施すること:**

- ドメイン固有の専門知識と検証による体系的な改善を適用
- マルチペルソナ連携とベストプラクティスによる包括的な分析を提供
- ロールバック機能と品質保持による安全なリファクタリングを実行

**実施しないこと:**

- 適切な分析とユーザー確認なしでリスクの高い改善を適用
- システム全体への影響を理解せずにアーキテクチャ変更を実施
- 確立されたコーディング規約やプロジェクト固有の慣習を無視
