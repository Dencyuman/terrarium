# Codex Plan Review

tasks/ ディレクトリの実装プランをレビューする。

## 対象プラン

!`ls -1 tasks/*.md 2>/dev/null || echo "tasks/ にプランファイルがありません"`

引数でファイルが指定されていればそれを、なければ現在のブランチに紐づくプランを検索する:

```bash
BRANCH=$(git branch --show-current)
grep -rl "branch: $BRANCH" tasks/*.md 2>/dev/null
```

該当がなければ最新（最大連番）のプランファイルを対象とする。

ARGUMENTS: $ARGUMENTS

## 手順

1. 対象プランファイルを特定して読み込む
2. プランの内容を分析する
3. 関連するコードベースを調査し、プランの前提が正しいか検証する
4. 以下の観点でレビューする:
   - **方針の妥当性**: 根本原因の特定は正しいか、修正方針は適切か
   - **完全性**: 見落としている変更ファイル、影響範囲はないか
   - **実現可能性**: 提案されたステップは実行可能か、技術的制約はないか
   - **エッジケース**: 考慮すべきエッジケースが漏れていないか
   - **検証方法**: テスト・検証の観点は十分か
   - **既存コードとの整合性**: 既存の命名規則・パターンに合っているか

## 出力フォーマット

```markdown
## プランレビュー結果: [プランファイル名]

### 総合評価
[方針は正しいか、実装に進んでよいかの判断]

### 指摘事項

#### [重要度: 高/中/低] タイトル
[指摘内容の説明]
**根拠**: [コードベース調査で確認した事実]
**提案**: [改善案]

### 検証済みの前提
[コードベース調査で確認できたプランの前提条件]

### 推奨アクション
- [ ] [対応すべき項目]
```

## ルール

- プランに記載されたファイルパス・型定義・関数名が実際に存在するか Grep/Read で検証する
- 指摘には必ずコードベース調査の根拠を含める
- コードの変更は行わない（レビューのみ）
- プランファイルの修正も行わない（フィードバックの提示のみ）
