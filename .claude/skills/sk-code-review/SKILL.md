# Code Review

現在のブランチの変更に対してコードレビューを実施する。

## 使用方法

```
/sk-review           # Codex でレビュー（デフォルト）
/sk-review codex     # Codex でレビュー
/sk-review claude    # Claude でレビュー
```

ARGUMENTS: $ARGUMENTS

## モデル選択

引数に `claude` が含まれる場合、以下の「手順」セクションに従い Claude 自身がレビューする。

引数が未指定または `codex` の場合、以下のコマンドで Codex CLI にレビューを委譲する:

```bash
codex exec "以下のブランチの変更をレビューしてください。品質・バグ・セキュリティ・パフォーマンスの観点で分析し、改善点を提示してください。タスクプランがあれば tasks/ ディレクトリから現在のブランチに紐づくファイルを読んで文脈として活用してください。コードの変更は行わないでください。"
```

Codex の出力結果をそのままユーザーに提示する。

## タスク文脈の取得

レビュー前に、現在のブランチに紐づくタスクプランを確認する:

```bash
BRANCH=$(git branch --show-current)
grep -rl "branch: $BRANCH" tasks/*.md 2>/dev/null
```

該当するタスクファイルがあれば読み込み、以下をレビューの文脈として活用する:
- Issue の目的・背景
- 実装プランの内容
- 変更予定ファイル一覧
- エッジケース・注意点

**タスクプランがある場合**: 変更がプランに沿っているか、プランで指摘されたエッジケースが対処されているかも評価する。

## 手順（Claude モード）

1. タスクプランを検索・読み込む（あれば）

2. ベースブランチ（staging）からの差分を取得する

```bash
git diff staging...HEAD
git log staging..HEAD --oneline
```

3. 変更ファイルを特定し、変更内容を読み込む

4. 以下の観点でレビューする:
   - **正確性**: ロジックのバグ、エッジケースの見落とし
   - **セキュリティ**: インジェクション、認証・認可の問題
   - **パフォーマンス**: N+1、不要な再レンダリング、メモリリーク
   - **保守性**: 命名、責務分離、コードの複雑さ
   - **型安全性**: TypeScript の型定義、any の使用
   - **プラン整合性**: タスクプランとの一致（プランがある場合）

5. 関連する既存コードも確認し、変更が既存機能に与える影響を評価する

## 出力フォーマット

```markdown
## レビュー結果

### タスク文脈
[紐づくタスクプランの概要。なければ「タスクプランなし」]

### サマリ
[変更の概要と全体評価]

### 指摘事項

#### [Critical] ファイル名:行番号
[重大な問題の説明と修正案]

#### [Warning] ファイル名:行番号
[注意すべき問題の説明と修正案]

#### [Info] ファイル名:行番号
[改善提案]

### 良い点
[評価できる変更点]
```

## ルール

- 変更されたコードのみをレビュー対象とする（周辺コードは文脈理解のために読むが、指摘はしない）
- 指摘には必ず具体的なファイルパスと行番号を含める
- 修正案を提示する場合は具体的なコードスニペットを含める
- コードの変更は行わない（レビューのみ）
