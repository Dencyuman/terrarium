# PR Review - プルリクエストレビュー

## 使用方法

```
/sk-pr-review [PR番号またはURL]
```

引数:

- `PR番号またはURL`: レビュー対象のPR（省略時は現在のブランチのPR）

ARGUMENTS: $ARGUMENTS

## 動作フロー

1. **PR取得**: `gh pr view` でPR情報とdiffを取得
2. **分析**: 変更内容をコード品質・セキュリティ・パフォーマンスの観点で分析
3. **コード読み込み**: 変更ファイルの前後コンテキストを `Read` で確認
4. **レビュー**: 問題点・改善提案・良い点をまとめる
5. **レポート**: 重要度別にレビュー結果を提示

## レビュー観点

- **品質**: コードの可読性、命名、責務分離、重複
- **セキュリティ**: インジェクション、認証・認可、入力バリデーション
- **パフォーマンス**: N+1クエリ、不要な再レンダリング、メモリリーク
- **保守性**: テスタビリティ、拡張性、依存関係
- **プロジェクト規約**: 既存パターンとの一貫性

## 出力形式

```markdown
## PRレビュー結果

**PR**: #番号 - タイトル
**変更**: +XX / -YY (NN files)

### 要修正
- **ファイル**: path:行番号
  - **問題**: 説明
  - **提案**: 修正案

### 改善提案
...

### 良い点
...

### 確認事項
- [ ] チェック項目
```

## 境界

**実施すること:**

- PR の変更内容を多角的にレビュー
- 問題点と改善提案を重要度別に整理して提示
- 変更の周辺コンテキストを考慮した深いレビュー

**実施しないこと:**

- PR へのコメント投稿（レビュー結果はユーザーに提示のみ）
- コードの自動修正
- PR の approve / request changes
