# Terrarium — v0.1 ビジュアル・演出仕様 (DESIGN)

本ドキュメントはプロジェクトのビジュアルデザイン、アセット選定、演出、UI/UX の視覚的な作り込みに関する仕様を定める。機能要件および実装計画は `docs/SPEC.md` を参照のこと。

## 1. デザインの基本方針

### 1.1 ビジュアル戦略の目的

Terrarium は観察専用の放置型シミュレーションであり、ユーザーは画面を「眺める」時間が長い。したがってビジュアルには次の3つの役割が求められる。

- **長時間眺めても疲れない、むしろ癒される**
- **重大イベント(死、戦争、誕生、制度発生)が起きても絵面が過度に重くならない**
- **スクリーンショット/動画として切り取られた時に、SNSで拡散される強度を持つ**

### 1.2 アートスタイル

**牧歌的パステル調の2Dトップダウン(Stardew Valley / Cozy Games 系統)**

この系統を採用する理由:

- 放置ゲームの文脈(長時間背景で走らせる)と親和性が高い
- 「観察して癒される」体験と一致する
- 死亡・戦争・殺害といった重い出来事が起きても、絵面が柔らかく保たれるため、ユーザーの心理的負荷が抑えられる
- SNS で拡散されやすい見栄えが保証されている(Stardew系フォロワーの投稿が示す通り)
- Microverse (KsanaDock) との直接の差別化にもなる(Microverse は Modern Interiors 系)

**採用しないスタイル**:
- ❌ シリアス/ダークファンタジー(Rimworld系): 長時間観察に向かない、死亡時の心理負荷が大きい
- ❌ ドット絵レトロ(Undertale系): 表現の解像度が低く、関係性・感情表現が伝わりにくい
- ❌ 3Dトップダウン: 実装コストが跳ね上がり、LLM処理との両立が厳しい
- ❌ リアル調イラスト: アセット入手が困難、統一感が取りにくい

### 1.3 色彩方針

**ワールド内(中央ビュー)**は Stardew 系の牧歌的パステルを維持する。**UI chrome(周辺)**はダーク計器盤とする。ワールドが発光しているように見える対比を作る。

- 草地: 黄緑から青緑のグラデーション(彩度中程度、明度中)
- 水域: くすんだ水色、夜は濃紺に寄る
- 森: やや暗めの緑、葉影のコントラストで立体感
- 岩場: グレーに茶色のアクセント
- UI chrome: **ダーク**(§4.1 の配色パレット参照)。ワールドの明るさを引き立てる黒板のような役割
- アクセント色: イベント通知 = 鮮やかな金/赤/ティール。接続インジケータ = 鮮緑

## 2. アセット選定

### 2.1 採用アセットの候補(推奨順)

#### 第1候補: LimeZu "Serene Village"

- 出典: itch.io (LimeZu)
- 価格帯: $10〜$15 前後(リビジョン含む)
- ライセンス: 商用利用可(Steam販売可)、LimeZuのライセンス条項に従う
- 特徴:
  - 村・自然・農地をテーマにした2Dトップダウンアセット
  - オートタイル対応の地形セット
  - 多数のキャラクターバリエーション(20体の見た目差別化が可能)
  - 感情アイコン、UI素材、エフェクトも同梱
  - Microverse が LimeZu 系を採用している実績(LLM多エージェント系との相性が確認済み)

#### 第2候補: Sprout Lands (Cup Nooble)

- 出典: itch.io
- 価格帯: $8.99 程度
- ライセンス: 商用利用可
- 特徴:
  - Stardew Valley 寄りのテイスト
  - 農地・村落に特化
  - キャラバリエーションはやや少ない

#### 第3候補: Cozy People / Cozy Farm (Shubibubi 等)

- 出典: itch.io
- 価格帯: $5〜$10
- パステル調の現代的な雰囲気

#### バックアップ: Kenney.nl (CC0)

- 出典: kenney.nl
- 価格: 無料 (CC0)
- 特徴:
  - 完全に自由に使えるが、スタイルが汎用的で「それっぽさ」は弱い
  - プレースホルダとしては最適

### 2.2 アセット導入方針

- **Phase 1〜8 は Kenney.nl またはプログラム生成のプレースホルダ**で開発を進める
  - Phase 1〜2 は **§3.9 のバッジのみモード**をデフォルトで採用し、スプライト未導入の状態でも観察・デバッグが成立する構成とする
  - Phase 3 以降、プレースホルダスプライト導入に合わせてハイブリッド表示(ピクセル + バッジ)を既定化する
- **Phase 9 で商用アセット(第1候補を想定)を一括導入**する
- アセット購入は v0.1 完成見込みが立った時点で実施する(¥2,000〜¥3,000程度の自費)

### 2.3 独自アセットの扱い

v0.1 では独自アセット(自作ドット絵等)は制作しない。購入アセット + 色調整のみで仕上げる。

## 3. 世界ビューの演出

### 3.1 タイルマップ

- **オートタイル対応**: 草地・水域・森・岩場の境界が自動的になめらかに繋がる
- Godot の `TileMapLayer` の terrain 機能を活用
- 同じ地形でも複数バリエーション(花が咲いた草、石のある草等)をランダム配置して単調さを避ける
- タイルサイズは 32×32 または 16×16 を想定(採用アセットに従う)

### 3.2 キャラクタースプライト

- **4方向(上下左右)向きごとのアニメーション**を持つ
- アニメーションステート:
  - 待機(idle): 呼吸のような揺れ、2〜4フレーム
  - 歩行(walk): 足踏み、4〜6フレーム
  - 死亡(die): しおれる、1回限り、1〜2秒
  - 抱擁(embrace): 隣接する相手との接触ポーズ
  - 攻撃(attack): 武器を振る or 殴る
- 20体のキャラは見た目でできる限り差別化する(髪色、服装、性別、年齢帯)
- 子エージェントは小さいサイズのスプライトに差し替える
- 老齢エージェントは髪色が白に寄る、動きがやや遅い等の視覚差をつける
- ピクセル単独では 20 体の瞬時識別が困難なため、§3.9 のハイブリッド表示(ピクセル + 頭上バッジ)を標準運用とする

### 3.3 エージェントの年齢表現

| 年齢帯 | スプライト表現 |
|---|---|
| 子ども | 小さいサイズ、頭身低め |
| 成人期 | 通常サイズ |
| 老齢期 | 髪色が薄/白、やや猫背、歩行速度低下 |

### 3.4 発話表現

- エージェントが `speak` した瞬間、頭上に **吹き出しポップアップ** を表示
- 吹き出しは RPG ツクール風のシンプルな角丸矩形
- 表示時間: 発話の長さに応じて 3〜6 秒、自動で消える
- 同時複数エージェントの発話は、吹き出しを少しずらして重ならないよう配置
- 吹き出しのテキストは発話全文の冒頭のみ(長文は「...」で切る)。全文は右パネルのログに表示

### 3.5 感情アイコン

エージェントの頭上に感情を示す小アイコンを一時表示する。

- `!` : 驚き、重大イベント観測時
- `?` : 疑問、困惑
- `♥` : 好意、抱擁時、子との接触時
- `怒` : 怒り、攻撃時
- `zZz` : 睡眠、休息
- `✨` : 発見、誕生、新規共有オブジェクトの観測時

トリガはアクションと状態遷移に紐づけて自動発生させる。

### 3.6 パーティクルエフェクト

重要イベントで画面を動かす。

- **誕生時**: 子エージェントの位置でキラキラが広がる、2秒程度
- **死亡時**: その場に小さい羽根や光が昇る、3秒程度
- **戦闘時**: 赤い衝撃エフェクト、短く
- **reproduce_with 成立時**: 両者の間にハートパーティクル
- **共有オブジェクト作成時**: 生成位置で書類が展開されるアニメーション

### 3.7 時間帯による色調変化

1日(N tick)のサイクルに合わせて画面全体の色調を変化させる。

| 時間帯 | 色調 |
|---|---|
| 朝 | やや黄色みがかった明るい色調 |
| 昼 | 通常の鮮やかな色調 |
| 夕 | オレンジ〜赤の色調 |
| 夜 | 青く暗い色調、エージェントの頭上に小さい光源 |

- 実装は `CanvasModulate` ノード + グラデーション切り替えで行う
- 夜間はエージェントが睡眠アクションを取りやすくなる(ただし強制はしない)
- **この機能はタイムラプス動画で非常に映えるため、SNS拡散の鍵となる**

### 3.8 共有オブジェクトの視覚化

- 地面に置かれた「書物」「立て札」「石板」のいずれかのスプライトで表示
- 作成からの経過時間で見た目が古びる(薄い色に変化)
- エージェントが `modify_object` した瞬間、短いフラッシュで変更を示す
- クリックで内容を吹き出し表示

### 3.9 エージェント表示モード(ハイブリッド表示)

ピクセルキャラ単独では 20 体の瞬時識別が困難であり、観察ツールとしての可読性を損なう。一方で丸アイコン単独にすると「生きている生物を神が眺める」というテラリウムのメタファーが失われ、演出・SNS映えも弱体化する。両者を併用することで、観察性とビジュアル品質を両立する。

#### 3.9.1 バッジ仕様

各エージェントの頭上に、**色付きの丸バッジ + 短い名前**を常時表示する。

- 形状: 直径 20〜24px の円(ピクセルスプライトの頭一つ分)
- 色: エージェント固有のアイデンティティカラー(§3.9.2 参照)
- 内部表記: 名前の1文字目(漢字名を想定、例:「霞」「朔」「桐」)
- 縁取り: 薄い白/黒の 1〜2px アウトラインで地形との視認性を確保
- 位置: スプライト頭上 +2〜4px、スプライトと重ならないよう配置
- 死亡後: 残骸表示中は半透明グレーに変化、消滅時にバッジも消える

#### 3.9.2 バッジ色の割り当て

色は**固定ではなくエージェントの属性からマッピング**する。デフォルトは性格3軸のうちもっとも強い軸:

| 性格優位軸 | 色系統 |
|---|---|
| 協調(cooperative 優位) | 緑系 |
| 攻撃(aggressive 優位) | 赤系 |
| 好奇(curious 優位) | 青/紫系 |
| 均衡(どの軸も50±10) | 黄/橙系 |

- 同系統内では明度/彩度で個別識別(例:同じ緑系でも 8 段階)
- この方針により、画面を一瞥するだけで**赤が多い村=攻撃的な世代**、**緑が増えている=協調的な子が生まれている**といった集団性格の変遷が直感できる(観察性の強化)
- 色覚多様性への配慮はバッジ内文字(名前1文字)で補強されるため実用上問題なし

#### 3.9.3 表示モード切替

ユーザーは以下 3 モードを切り替え可能とする。デフォルトはハイブリッド。

| モード | 表示内容 | キー | 用途 |
|---|---|---|---|
| ハイブリッド(既定) | ピクセル + 頭上バッジ | - | 通常の観察、識別性と演出の両立 |
| ピクセルのみ | ピクセル、バッジ非表示 | `V` トグル | スクリーンショット撮影、タイムラプス動画、SNS投稿用 |
| バッジのみ(ダッシュボード) | ピクセル非表示、バッジのみ | `V` トグル | 長時間観察・デバッグ時、誰が何をしているかの追跡最優先 |

- 切替は `V` キーの 3 段階ローテーション(ハイブリッド → ピクセルのみ → バッジのみ → ハイブリッド)
- UI 右上にも小さなトグルボタンを配置
- モードは設定に保存され、次回起動時も引き継ぐ

#### 3.9.4 ズーム連動自動切替(v0.2 検討)

- ズームアウト時はピクセルが潰れて読めなくなるため、一定縮尺以下ではバッジのみモードへ自動フォールバック
- v0.1 では手動切替のみ、自動切替は v0.2 で実装

#### 3.9.5 関連ビューでの扱い

- 関係性グラフ・家系図: **バッジと同じ色・名前表記**でノードを描画し、ワールドビューとの視覚的同一性を保つ(どのビューでも「赤の樅」は樅と即座にわかる)
- エージェント詳細ダイアログ: 大きなピクセルアバター + 大きなバッジを並置
- ログパネル: 発話者名の横にバッジ色を小さいドットで表示(§4.3 のログ行アイコンに統合)

## 4. UI デザイン

### 4.1 全体のトーン(観察装置 / Observation Chamber)

UI は世界を眺めるための**計器盤**として設計する。主役はあくまで中央のワールドビューであり、周辺 UI は情報密度の高い暗色クロムで世界を額装する。

- **チェーマ**: ダーク chrome + 生命感のあるワールド中央。UI は世界より目立たない "black box" として、世界が発光しているように見える配色
- **配色パレット**:
  - 背景ベース: `#1a1d24`(ほぼ黒、わずかに青みの冷灰)
  - パネル面: `#23272f`(1段明るい濃灰)
  - パネル縁: `#353a43`(細いラインのみ、角丸は控えめ 4px)
  - 見出し/主テキスト: `#e6e4de`(温かい白)
  - 副テキスト/ラベル: `#8a8680`(くすんだ灰褐)
  - オンライン/接続インジケータ: `#6eda8a`(鮮緑)
  - 赤アラート: `#e07070`
  - アクセント: `#6acfb0`(ティール、タブ選択状態)
  - ワールド内タイル色は §1.3 の自然色を維持(UI 暗色 × 世界色の対比で世界が輝く)
- **フォント**: 日本語対応 SystemFont(Hiragino Kaku Gothic / Noto Sans CJK JP / Yu Gothic の順にフォールバック)。等幅が欲しい箇所(tick / ログの時刻カラム)は別途 monospace SystemFont を用意
- **角丸**: 4px のみ(従来のパステル案の柔らかい角丸は廃止)
- **影**: ほぼ使用しない。パネルは面と縁だけで構成、必要ならインナーシャドウで沈み込みを出す
- **ボタン**: 既定は flat(背景透明)+ 選択時のみ `#3a4048` に反転。ホバーで縁色がアクセント色にフェード

### 4.3 ログパネル(発話ログ)

- 新しい発話/イベントが**上から**流れる(Twitter タイムライン方向)
- 1 行構造: `[tick] [バッジ] 名前: 発話内容`
  - tick は等幅モノスペース、副色(#8a8680)
  - バッジは §3.9.1 と同一ビジュアルの小サイズ(12px)
  - 名前はバッジ色と同系のやや明るい色で 1 色、発話本文は白
- イベント(誕生/死亡/戦闘/共有オブジェクト生成)は**プレフィックス行**として挿入(背景をわずかに着色)
  - 誕生: 左端に 💫 と金色ライン
  - 死亡: 左端に 🕊 とグレーライン
  - 戦闘: 左端に 💢 と赤ライン
  - 共有オブジェクト: 左端に 📜 とアンバー
- パネル上部右に「最新N件」カウンタとフィルタ(v0.2 で実装)
- ホイールスクロールで履歴を遡れる

### 4.4 再生コントロール(ステータス帯内)

デザイン方針の変更により、再生コントロールは専用バーではなく**ステータス帯に統合**する(`[Tick NNN] [II][1x][2x][5x]` を横並び)。

- pause/play トグルボタン(アイコンのみ 32×32)
- 1x / 2x / 5x を三択のトグルグループ。選択中のみ `#3a4048` にハイライト、他は flat
- リセットはタブ群の隣に小さく配置(`↻ RESET`)。押すと確認ダイアログ
- キーボードショートカット: Space(pause)、1/2/3(速度)、R(reset)、V(表示モード §3.9.3)

### 4.5 エージェントリストサイドバー(左上)

全エージェント(世代・生死混在)を縦スクロールで一覧。

- 各行: `[バッジ] 名前 性別 Age♥好感度`
  - バッジ: §3.9.1、18×18 のミニサイズ
  - 「♥数」はプレイヤー視点の**注目度**として、本人を中心とした関係の総量(好感度+被好感度の平均)を簡易表示
  - 直下に細い健康バー(体力/空腹度)を 2 本重ねて描画
  - 右端に状態アイコン(会話中 💬 / 食事中 🍀 / 戦闘中 💢 / 休息 zZz)
- 選択行は左端にアクセント色の縦帯、背景が `#2a2e36` に反転
- 死亡者は半透明(0.5)で表示、年齢の後ろに † と死亡日を表示(v0.1 は非表示で v0.2 で足す候補)
- 並び順: 年齢降順をデフォルト。プルダウンで「好感度順 / 名前順 / 世代順」切替(v0.2)

### 4.6 エージェント詳細カード(左下)

エージェントリストまたはワールドでクリックされたエージェントの詳細を表示。

- ヘッダ: `[バッジ] アカネ ♀ Age 34  [✕]` 閉じるボタン付き
- 状態バー: 空腹度 / 体力(それぞれ数値 + 100 分率)
- 性格: 協調 / 攻撃 / 好奇 の 3 本バー(0-100)
- 現在の行動: 例「会話中(ギン)」
- 場所: `(x, y) 地形名`
- 世代: `G1` 等
- 子供: 人数
- 「詳細を見る」ボタン: §4.13 の大きなダイアログを開く
- カードが閉じている場合、この領域は空のパネル(または「エージェントを選択してください」のヒント)

### 4.7 アクションパネル(中央下)

Decide フェーズで決定された意思決定を**直近 tick で特筆すべき 5 名分**カード表示。観察者がその tick に何が起きているかを即座に把握できるようにする。

- カードヘッダ: `[バッジ] 名前` + アクションアイコン
- 一行サマリ: 「アクション名(対象)」(例: `会話(アカネ)` `移動(9,12)` `採取(果実)`)
- 理由: LLM が返した reasoning の短縮(1〜2文、全文はホバーで展開)
- 選択ロジック(v0.1): 単純に最初の 5 名。v0.2 以降で「重要イベント寄与度でソート」を検討
- パネル下端に: `フェーズ: Decide (意思決定中)` + `並列処理: 3/4` のプログレスバー
- Commit 後は「最新アクション」として固定表示し、次の Decide で更新

### 4.8 ミニマップ(ワールドビュー右上)

- 20×20 をワールドの 1/8〜1/10 スケールで右上隅に常時表示
- エージェントはバッジ色の 1px ドットで位置だけ示す(名前文字なし)
- 現在のカメラビューポートを黄色矩形で重ねて表示
- クリック: その座標にカメラジャンプ
- v0.1 では ViewPortTexture 再描画ではなく `_draw()` での簡易描画で実装

### 4.9 フッターステータス

- 左: `● モデル gemma4:e4b (thinking: OFF)` モデル設定を即座に確認できる
- 中: `● 接続 Ollama localhost:11434` Ollama が応答しているかのライブインジケータ
  - 緑: 応答あり
  - 黄: レスポンス遅延(>10s)
  - 赤: 接続失敗 or タイムアウト連続
- 右: `[ログを開く]` シミュレーションのローカルログファイル(v0.2 で本実装)を開くボタン

### 4.10 関係性グラフビュー

- ノード: 各エージェントをアバターアイコン付きの円で表示
- エッジ: 関係の強さで太さ、種類(親子/敵対/友好)で色分け
- 現在生きているエージェントは濃い色、死亡者は半透明
- 物理シミュレーションベースのレイアウト(Force-directed graph)
- ホバーでエッジの詳細(「Alice は Bob を信頼している: 78%」等)を表示

### 4.11 家系図ビュー

- 縦軸が世代(上が古い、下が新しい)
- 親子関係を線で接続
- 結合関係(reproduce_with したペア)は横線で接続
- 死亡者は肩書き部分に「†」マークと死亡日

### 4.12 イベント年代記(右下パネル)

- 右下パネルに縦スクロールで一覧(mockup 準拠。横スクロールのタイムライン表示は廃止)
- ヘッダにフィルタタブ: `[全て][出生][死亡][戦闘][オブジェクト][教育]`(v0.1 は全て、フィルタは v0.2)
- 各エントリ: `[アイコン] DayXXX tickNNNN 本文`
  - アイコン色分け(§4.3 と同系統): 誕生=金、死亡=灰、戦闘=赤、共有オブジェクト=アンバー、教育=青緑
  - 本文は発話ログより長め(2 行まで)の説明文
- 年代記とタイムラプス動画の元データを兼ねる(v0.2 で書き出し対応)

### 4.13 エージェント詳細ダイアログ(モーダル)

- 世界ビューのエージェントをクリックで開く
- 表示内容:
  - 大きなアバター画像
  - 基本情報(名前、年齢、性別、性格タグ)
  - 現在の状態(空腹、体力)
  - 直近の記憶(ローリングログ)
  - 日次サマリの一覧
  - 関係リスト(好感度順)
  - 家系情報(両親、子、きょうだい)

## 5. カメラワーク

### 5.1 基本操作

- マウスドラッグ: パン(視点移動)
- マウスホイール: ズームイン/アウト
- 右クリック: 画面中央にエージェントを追尾するモードに切替

### 5.2 自動演出

- **重大イベント発生時のズームイン**: 死亡、誕生、戦闘、reproduce_with、create_shared_object の瞬間に、該当地点へ短時間(1〜2秒)カメラをフォーカス
- **観測モード**: ユーザーが一定時間操作しない場合、興味深いイベントが起きた場所へカメラが自動的に漂う
- **タイムラプスモード**: カメラが遠景視点に固定され、速度 5x で進行。X投稿用の動画撮影を想定(v0.2 で本格実装、v0.1 ではマニュアル速度切替で代用)

## 6. 音響設計

### 6.1 v0.1 の方針

- **環境音のみ実装**: BGMは v0.1 では持たない
- 環境音: 草原の風音、鳥の声、水のせせらぎ、夜の虫の音
- ループ再生、時間帯に応じて切替

### 6.2 効果音(Phase 9で必要に応じて)

- 発話: 控えめなポップ音
- 誕生: 明るい鈴の音
- 死亡: 落ち着いた鐘の音
- 戦闘: 短い打撃音
- 共有オブジェクト作成: 書き物の音

### 6.3 v0.2 以降の検討

- BGM の導入(素材は Itch.io や OpenGameArt から)
- 音量調整 UI
- ユーザー側で BGM オフ可能に

## 7. スクリーンショット・動画映えの設計

### 7.1 SNS投稿を前提とした画面作り

- 常時、画面のどこを切り取っても絵になる状態を目指す
- 重大イベント時には自動スクリーンショット撮影機能を検討(v0.2)
- 画面端に余計な情報を詰め込まない。余白を恐れない

### 7.2 動画撮影に向けた設計

- タイムラプス機能(v0.2):
  - 特定の日付範囲の動きを動画として書き出し
  - 家系図や関係性グラフの変化もタイムラプス化
- Discord/Twitter への直接投稿ボタン(v0.3 以降)

### 7.3 シェアしやすい単位の提示

- 「昨日の村の一日」ダイジェスト表示
- 「〇〇の生涯」個人史ビュー
- 「家系図で見る100年」世代タイムラプス

## 8. アクセシビリティ

v0.1 では深く踏み込まないが、最低限のみ配慮する。

- ボタンのクリック判定は十分な大きさ
- 文字サイズは中程度以上(12pt以下は使わない)
- 色のみに依存する情報提示を避ける(アイコンと組み合わせる)
- カラーブラインド対応のパレットは v0.2 以降で検討

## 9. ビジュアル品質の完成定義

Phase 9 完了時点で以下をすべて満たすこと(SPEC.md の成功条件 11 に対応)。

1. 世界ビューがプレースホルダではなく、統一感のある商用アセットで描画されている
2. キャラクターが4方向アニメーションで歩行している
3. 発話時に吹き出しが表示される
4. 少なくとも 4 種類以上の感情アイコンが自動表示される
5. 時間帯による色調変化が機能している
6. 誕生・死亡・戦闘・reproduce_with 各イベントにパーティクルエフェクトが表示される
7. UI が §4.1 のダーク観察装置テーマで統一され、フォント・配色・枠線が一貫している
8. 関係性グラフ、家系図、イベント年代記が機能的かつ見やすく描画されている
9. スクリーンショットを撮影してSNSに投稿することに抵抗のない品質となっている(作者の主観判断)
10. 重大イベント発生時に自動的にカメラフォーカスが働く
11. ハイブリッド表示(ピクセル + 頭上バッジ)が動作し、`V` キーで 3 モードを切り替えられる。バッジ色・名前がワールドビュー/関係性グラフ/家系図/ログ/エージェントリストで一貫している
12. エージェントリスト・詳細カード・アクションパネル・ミニマップ・フッターステータスが §4.5〜§4.9 の仕様を満たして動作する

## 10. 参考にするプロダクト

ビジュアル/UX の方向性の参考として以下を参照する。

- **Stardew Valley** — 中央ワールドの色調/タイル雰囲気(パステル緑基調、長時間プレイ向け)
- **Rimworld** — 出来事ログの流れ方、ダーク UI の情報密度(ビジュアルは真逆だが UI 密度は近い)
- **The Sims シリーズ** — キャラクター感情表現、関係性UI
- **Civilization シリーズ** — 年代記(イベント履歴)の見せ方、ミニマップ構成
- **Factorio** — ダーク chrome + ワールド中央発光の計器盤的 UI 構成
- **Microverse (KsanaDock)** — 直接の類似プロダクト。UI 面ではダーク観察装置路線で差別化
