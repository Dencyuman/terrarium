# Jev / Luna — Web版の認知処理

更新日: 2026-09-18。Godot向け初期改修案を、現在のTypeScript実装に合わせて更新した。

## 役割

| 処理 | 担当 | 出力 | tickとの関係 |
| --- | --- | --- | --- |
| 物理条件・候補列挙・実行 | TypeScript | 実行可能な行動と世界の変化 | 同期 |
| 即時判断（System 1） | Jev | 行動候補の確率、再考の必要性 | 同期 |
| 熟考（System 2） | GPT-5.6 Luna | 目標・信念・優先事項・計画 | 非同期 |
| 発話・教育 | GPT-5.6 Luna | 選択済み行動の本文 | 同期 |
| 従来方式 | GPT-5.6 Luna | 最大5件の行動 | 同期 |

Jevに自由文のコメントを生成させたり、プリセットコメントを選ばせたりはしない。無料デモだけは、ルールによる判断と例文を使う。

## 個体に渡すもの

`src/simulation/cognition.ts` の `observation` が、本人の身体・性格・所持品・認知・関係・記憶と、周囲3マスの地形・資源・他者の様子を構成する。

視界外の他者の現在の体力や生死、観察者向けの世界全体の年代記を渡さない。自身が記憶している人物への関係や、過去に見た場所の記録は保持する。

記憶には経験・目撃・伝聞の区分、出典、関連人物、時刻、位置がある。AI世界では本人の長期記憶をSQLiteから取得し、人物との関連と新しさで絞る。プロンプトへ渡す関連記憶は最大10件、各240文字。伝聞の内容を全知の正解で書き換えない。

## Jevのリクエスト

`worker/ai.ts` からTypeSafe System One APIの `jev-latest` を呼ぶ。個体ごとに1リクエスト、世界あたり最大20並列で処理する。

同一リクエストへ以下の質問をまとめる。

1. **Choice**: 実行可能な具体的候補のどれを選ぶか。
2. **Noul**: 現在の目標・認識を再考する必要があるか。
3. **追加Noul**: 目標に意味的な成功条件がある場合、その達成度。

11種類の動詞に方向・相手を付けた候補を列挙する。候補は状態を変更せず生成し、選択確率・選択ID・候補ラベル・再考値を `Judgment` に保存する。

タイムアウトは12秒。特定の一時エラー（429、529、500、502、503、504）だけを再試行し、試行回数を制限する。失敗時はエラーを記録し、行動は休息にフォールバックする。

## tickの進め方

1. 前回までに完了した熟考を境界で反映する。
2. このtickに参加する生存者と、その観測を固定する。
3. 個体ごとにJevを呼び、必要な熟考を非同期で開始する。選ばれた発話・教育があればLunaの本文を待つ。
4. 全個体の結果がそろってから、ID順に物理処理する。
5. 代謝・出生・死亡・資源再生を進め、完了した熟考を再び境界で反映する。
6. 世界と利用量を保存し、ブラウザへ返す。

APIの返却順で実行順は変わらない。実行時には位置や対象の生死、資源を再検証する。先に他者が食料を拾った場合などは失敗する。出生した子の判断は次tickから。

発話の生成中は、そのtick全体が待つ。複数の発話は並列に処理されるが、最も遅い個体の処理が終わるまで確定できない。現在はこの同期方式を採用している。

## 非同期の熟考

Jev判断後、以下のいずれかで再考の候補になる。

- 再考のNoul値が `deliberationThreshold`（既定0.7）より大きい。
- 最上位の候補確率が `top1Threshold`（既定0.5）より小さい。
- 上位2候補の差が `marginThreshold`（既定0.1）より小さい。

既に思考中の個体・判断エラーの個体は起動しない。個体あたり既定5 tickの間隔を空け、世界ごとに最大2件を同時実行する。OpenAIキーが必要。

出力は `goal`、`beliefs`、`priorities`、`plan`。直接の行動実行機能は与えない。HTTP完了時に結果を待機キューへ入れ、tickの開始・終了境界で採用する。観察を止めている間に世界を進める処理ではない。

### 古い結果の扱い

開始時のworld ID・認知revision・tick・本人の体力・既知の生存者を記録する。次の場合は結果を破棄する。

- 世界または認知revisionが変わった。
- 本人が死亡した。
- 既定10 tickを超えて古くなった。
- 本人が新たに体力30未満の重傷になった。
- 既知の人物がいなくなった、または死亡を本人が記憶した。

tickが進んだことだけで破棄しない。再起動時に未完了の熟考を自動再実行しない。失敗・破棄・完了は状態とイベントに残る。

## 目標と検証

目標は説明、優先度、成功条件、制約、関連人物ID、生成tickを持つ。成功条件は以下の4種類。

| 条件 | 評価 |
| --- | --- |
| `inventory_count` | 所持数をコードで比較 |
| `position` | 現在座標をコードで比較 |
| `health` | 体力をコードで比較 |
| `semantic` | JevのNoul。0.8以上を達成の目安とする |

意味条件の未評価は「不明」とし、評価tickと確率を保存する。構造、数値範囲、所持上限、座標、既知の人物への参照を検証する。文章の前提や実現可能性すべてを保証する検証ではない。

## 発話・教育とOpenAI

Jevで決定済みの種類と相手を固定して本文だけを依頼する。`speak` / `teach` 以外では本文生成APIを呼ばない。キー未設定時はこの2種類をJevの候補から外す。

Responses APIを使い、モデルは `OPENAI_MODEL`（既定 `gpt-5.6-luna`）。strict JSON Schema、推論設定 `none`、`service_tier=default`、`store=false`、出力上限900トークン。発話は10秒、熟考・従来方式は25秒でタイムアウトする。

拒否・打ち切り・不正な出力・API失敗を正常な本文として使わない。発話失敗は休息として記録し、例文で補完しない。利用量が返った失敗は費用にも計上する。

## 利用量と表示

即時判断・熟考・言語・従来方式の4区分で、要求数、入力・出力トークン、費用、遅延、失敗を記録する。Lunaのキャッシュ利用量と長文入力の倍率も費用計算に反映する。未登録のモデル価格は推測せず、未集計があることを表示する。

デモはAPI利用として数えない。画面の計算値は概算で、請求額や金額上限を保証するものではない。

## 実装と検証

- `src/simulation/actions.ts`: 候補と物理条件
- `src/simulation/cognition.ts`: 観測、記憶選択、再考条件、目標検証
- `src/simulation/thought.ts`: 熟考結果の採用・破棄
- `worker/ai.ts`: TypeSafe / OpenAI接続、構造化出力、利用量
- `worker/index.ts`: 並列判断、同期発話、非同期熟考、保存
- `tests/ai.test.ts`・`tests/thought.test.ts`・`tests/simulation.test.ts`: 応答、知覚、認知と物理の境界
